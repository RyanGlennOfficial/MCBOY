# McBoy 0.9 architecture

`McBoyAudioProcessor` exposes 106 JUCE APVTS parameters: 100 stable numbered effects, six utility parameters. The original GUI shows all 100 miniature knobs, grouped ten per bank. Randomize / locks / history / seed / A/B slot / state persistence happen on the JUCE message/UI thread and never inside the audio callback. Each process block copies cached parameter atomic values into a POD `CoreControls` packet.

`mcboy::Engine` (JUCE-independent) preallocates 2-second history rings, ping-pong lines, four comb lines per channel, flanger lines, an `ExtraEffects` nonlinear feedback memory, and a separate `SpectralBlur` STFT with preallocated FFT/overlap buffers. In `process()`, all effect parameters are smoothed toward `raw×degree` over ~28 ms and then routed into bounded parallel send outputs. Twenty-nine original effects live directly in `Engine.h` and 71 additional effects in `ExtraEffects.h`. Wet returns are summed with normalized weights, followed by selected master stereo operations, master MIX, OUTPUT dB, and an optional sample peak soft guard. Bypass is a smooth dry-path crossfade.

A deterministic SplitMix64 PRNG stores a patch seed. Locking affects randomization but not manual adjustment or automation. Randomize selects up to four active controls per bank, sparsity shaped by DEGREE. Utility commands also include 20-step Undo/Redo and a serialized stored A/B comparison slot. The standalone tests target the DSP directly. `JuceProcessorSmoke` is intended to validate the wrapper on a machine with JUCE; it has not yet been executed here.

Minimum JavaScript/web runtime is NOT involved. The actual desired distributable is a native C++ VST3 bundle generated by JUCE+CMake+Xcode, plus an optional standalone diagnostic target. No AAX binary is included, and Pro Tools does not directly host VST3.
